🔢 1. ระบบเลข
1101₂ = 8 + 4 + 0 + 1 = 13  ·  0x2F = 2×16 + 15 = 47  ·  0x2F = 0010 1111₂
  • ฐาน 10 → 2: หารด้วย 2 ซ้ำ ๆ อ่านเศษจากล่างขึ้นบน · ฐาน 2 ↔ 16: จับกลุ่มทีละ 4 บิตจากขวา
  • Two's complement (ค่าลบ): กลับบิตทั้งหมดแล้ว +1 เช่น −5 ใน 8 บิต = 1111 1011₂ · ช่วง n บิต = −2ⁿ⁻¹ … 2ⁿ⁻¹−1

➕ 3. Half Adder · Full Adder · Ripple-carry
Half: S = A ⊕ B · C = A·B
Full: S = A ⊕ B ⊕ Cin · Cout = AB + Cin(A ⊕ B)

Full Adder = Half Adder 2 ตัว + OR · ต่อ 4 ตัวเป็น 4-bit adder carry วิ่งจาก LSB → MSB · Cout = 1 → overflow เช่น 9 + 8 = 17 = 1 0001₂

ripple-carry ช้าเมื่อบิตมาก เพราะต้องรอ carry ผ่านทุกบิต → CPU จริงใช้ carry-lookahead

วงจรเชิงผสม (combinational)วงจรเชิงลำดับ (sequential)
เอาต์พุตขึ้นกับอินพุตปัจจุบันเท่านั้นอินพุต + สถานะเดิมที่จำไว้
ตัวอย่างadder, MUX, decoder, ALUflip-flop, register, counter

🔁 5. CPU และวงรอบ Fetch–Decode–Execute
ALUคำนวณเลขและตรรกะ (ภายในคือ adder + เกต)
Control Unitถอดรหัสคำสั่งและส่งสัญญาณควบคุม
PC / IRPC = ที่อยู่คำสั่งถัดไป · IR = คำสั่งที่กำลังทำ
Registerหน่วยความจำเร็วสุดใน CPU เช่น x0–x31 ของ RISC-V
ขั้นตัวอย่าง add x3, x1, x2 (x1 = 6, x2 = 7)
1 Fetchอ่านคำสั่งที่ PC = 0x100 จาก memory → IR
2 DecodeCU แปล: บวก x1 กับ x2 เก็บ x3
3 ExecuteALU: 6 + 7 = 13
4 Write backx3 ← 13 · PC ← PC + 4 (คำสั่งยาว 32 บิต = 4 ไบต์)

pipeline = ทำหลายคำสั่งซ้อนกันคนละขั้น เหมือนสายพานซักผ้า-อบ-พับ · cache ลดเวลารอ memory

⚠️ ข้อผิดพลาดที่พบบ่อย
  • อ่านเศษการหารจากบนลงล่าง (ได้เลขกลับด้าน) · ลืมว่า A–F = 10–15 · จับกลุ่ม 4 บิตจากซ้าย
  • สับสน OR กับ XOR ที่แถว 1 1 (OR = 1, XOR = 0) · คิด AND ก่อน NOT ผิดลำดับ
  • ลืม carry จากบิตก่อนหน้า (ใช้ half adder ทุกบิต) · ลืมว่า Cout = 1 คือ overflow
  • คิดว่า PC เก็บ "คำสั่ง" — PC เก็บที่อยู่ ส่วน IR เก็บคำสั่ง
  • คิดว่า RISC-V คือชิปรุ่นหนึ่ง — RISC-V คือ ISA ผู้ผลิตหลายรายนำไปสร้างชิปเอง
✅ เช็กความเข้าใจ
  • แปลง 1101₂, 0x2F เป็นฐานสิบ และ 13 เป็นฐานสองได้
  • เขียนตารางความจริงของ AND/OR/NOT/XOR/NAND และหาค่านิพจน์ทีละขั้นได้
  • อธิบายว่าทำไม XOR + AND = half adder และบวก 4 บิตแบบ ripple-carry ได้
  • อธิบาย fetch–decode–execute และบทบาทของ PC, IR, ALU, CU ได้
  • เปรียบเทียบ von Neumann กับ Harvard และ CPU/GPU/NPU ได้
  • สร้าง half/full adder ใน Logisim ให้ตรงกับผลจาก Python ทุกแถวได้
