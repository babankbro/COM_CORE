🧾 4. Evidence vs Interpretation vs Opinion
ชนิดตัวอย่าง
Evidence"rack มีป้าย hot aisle / cold aisle" · "ประตูมีบัตร + biometric 2 ชั้น"
Interpretation"แยกลมร้อน/เย็นช่วยลดพลังงานระบบเย็น → PUE ต่ำลง (W7)"
Opinion"ประทับใจความเป็นระเบียบ" (ใส่ได้ แต่ไม่แทน evidence)

ตัวเลขที่ได้ยินให้ระบุแหล่ง ("ตามที่วิทยากรกล่าว") ห้ามแต่งตัวเลขเพิ่ม

📝 6. โครงร่างรายงานการดูงาน (10%)
  1. ข้อมูลทั่วไป: หน่วยงาน วันเวลา ผู้บรรยาย
  2. สิ่งที่สังเกต/เรียนรู้: เทคโนโลยี กระบวนการ การจัดองค์กร
  3. เชื่อมโยงเนื้อหารายวิชา ≥ 3 หัวข้อ (ระบุสัปดาห์)
  4. บทบาทอาชีพที่พบ + ทักษะที่ต้องการ
  5. ข้อคิด / คำถามที่ยังสงสัย
  6. ภาพประกอบ ตามที่หน่วยงานอนุญาต (CIA + PDPA)

ใช้ AI ช่วยเรียบเรียง → เปิดเผยการใช้ และตรวจข้อเท็จจริงเอง (W13)

🤝 7. จรรยาบรรณระหว่างดูงาน + คำถามวิทยากร
  • ถามก่อนถ่ายภาพ: rack, dashboard, แผนผังอาคาร อาจเป็นข้อมูลลับ (Confidentiality)
  • เบลอใบหน้า/ชื่อบนบัตรพนักงาน = ข้อมูลส่วนบุคคล
ควรถามไม่ควรถาม
ทักษะใดที่นักศึกษาปี 1 ควรเริ่มฝึกเงินเดือนของพนักงานแต่ละคน
วัดความน่าเชื่อถือของระบบด้วย metric ใดระบบเคยถูกเจาะผ่านช่องโหว่ไหน
ลดพลังงานระบบเย็นอย่างไรลูกค้ารายใหญ่/ราคาสัญญา
👩‍💻 8. บทบาทอาชีพ + T-shaped skills

Embedded · IoT · Chip design · Network · Cloud · DC Ops · DevOps/SRE · Data · ML · Security engineer — ดู "หน้าที่" มากกว่าชื่อตำแหน่ง · T-shaped = รู้กว้างหลายด้าน (แกนนอน) + ลึก 1 ด้าน (แกนตั้ง) + lifelong learning

⚠️ ข้อผิดพลาดที่พบบ่อย
  • จดแต่ความรู้สึก ("น่าทึ่งมาก") ไม่มี evidence
  • เชื่อมรายวิชาไม่ถึง 3 หัวข้อ หรือไม่ระบุสัปดาห์
  • ถ่าย/โพสต์ภาพโดยไม่ขออนุญาต · ไม่เบลอข้อมูลส่วนบุคคล
  • สับสน PUE: ค่ายิ่งต่ำ (ใกล้ 1.0) ยิ่งดี
  • คัดลอกข้อมูลจากเว็บบริษัทโดยไม่อ้างอิง
✅ เช็กความเข้าใจ
  • ระบุชั้นใน value chain ของหน่วยงานที่ไปดูงานได้
  • ใช้ 6 มุมสังเกตจดหลักฐานและโยงสัปดาห์/CLO
  • แยก evidence / interpretation / opinion ได้
  • คำนวณและตีความค่า PUE ได้
  • เขียนรายงานครบ 6 ส่วนโดยเคารพความลับและ PDPA
