🧩 1. อัลกอริทึมและการคิดเชิงคำนวณ

Algorithm = ลำดับขั้นตอนที่ชัดเจน จบได้ แก้ปัญหาได้ (เหมือนสูตรอาหาร) · Program = อัลกอริทึมที่เขียนด้วยภาษาที่เครื่องเข้าใจ

คุณสมบัติ 5 ข้อ: Input · Output · Definiteness (ชัด ตีความทางเดียว) · Finiteness (จบได้) · Effectiveness (ทำได้จริง)

Decompositionแบ่งปัญหาใหญ่เป็นปัญหาย่อย (รับข้อมูล → ประมวลผล → แสดงผล)
Patternหาส่วนที่ซ้ำกัน → ใช้ลูป/ฟังก์ชันเดียวกัน
Abstractionตัดรายละเอียดที่ไม่จำเป็น เก็บเฉพาะที่ใช้ตัดสินใจ
Algorithmเขียนขั้นตอนเป็น pseudocode / flowchart ก่อนเขียนโค้ด

โครงสร้างควบคุม 3 แบบ: ลำดับ (sequence) · เงื่อนไข (if/else) · วนซ้ำ (for/while)

📈 3. Big-O: ข้อมูลโตขึ้นแล้วช้าลงแค่ไหน
Big-Oตัวอย่างn = 1,000n = 10⁶
O(1)lst[i], d[key], x in set (เฉลี่ย)11
O(log n)binary search10~20
O(n)linear search, หา max, sum()1,00010⁶
O(n log n)sorted(), merge sort9,966~2×10⁷
O(n²)ลูปซ้อน 2 ชั้นเทียบทุกคู่10⁶10¹²
  • ต่อกัน → บวก แล้วเก็บตัวใหญ่สุด: O(n) + O(n²) = O(n²) · ซ้อนกัน → คูณ: n × n = O(n²)
  • ตัดค่าคงที่: 3n + 5 = O(n) · ลูปที่ i ถูกหาร 2 ทุกรอบ = O(log n)
  • Best / Average / Worst case (Big-O มักหมายถึง worst) · วัดเป็น "จำนวนขั้น" ไม่ใช่เวลา
💻 โค้ด Lab 04: Linear vs Binary search
def linear_search(data, target): # O(n) for i, value in enumerate(data): if value == target: return i return -1 def binary_search(data, target): # O(log n) data ต้องเรียงแล้ว low, high = 0, len(data) - 1 while low <= high: mid = (low + high) // 2 if data[mid] == target: return mid elif data[mid] < target: low = mid + 1 # ครึ่งขวา else: high = mid - 1 # ครึ่งซ้าย return -1

scores = [12, 25, 31, 47, 58, 63, 77, 84, 90, 99] หา 77: linear ดู 7 ตัว · binary 4 รอบ (mid = 4 → 7 → 5 → 6)

🤖 6. ใช้ AI Coding Assistant อย่างรับผิดชอบ

AI = นักบินผู้ช่วย (next-token prediction) ไม่ใช่นักบินอัตโนมัติ · ผู้เรียนรับผิดชอบโค้ดที่ส่ง

  1. เขียน prompt ชัด: โจทย์ อินพุต เอาต์พุต กรณีขอบ ภาษา/ข้อจำกัด
  2. อ่านและอธิบายโค้ดได้ทุกบรรทัด → ขอให้ AI อธิบาย Big-O
  3. เขียน test เอง (ลิสต์ว่าง ค่าติดลบ ตัวเดียว) แล้วรันจริง
  4. ไม่ผ่าน → ส่ง error เต็มกลับไปถาม · ผ่าน → commit
  5. บันทึกการใช้ AI ใน docs/progress-log.md (academic integrity)

ความเสี่ยง: hallucination (API ที่ไม่มีจริง) · bug เชิงตรรกะ · ช่องโหว่ความปลอดภัย · ข้อมูลลับรั่ว · ลิขสิทธิ์

⚠️ ข้อผิดพลาดที่พบบ่อย
  • เริ่ม best = 0 ตอนหาค่าสูงสุด → ผิดเมื่อคะแนนติดลบทั้งหมด ต้องเริ่มจาก scores[0]
  • ใช้ binary search กับข้อมูลที่ยังไม่เรียง → ได้คำตอบผิดโดยไม่มี error
  • วัดอัลกอริทึมด้วยเวลา (ms) ครั้งเดียว — เวลาขึ้นกับเครื่อง ให้ดูจำนวนขั้น/แนวโน้ม
  • คิดว่า O(n²) "แค่ช้ากว่านิดหน่อย" — n = 10⁶ ต่างจาก O(n) ระดับมิลลิวินาทีกับชั่วโมง
  • "รันได้ = ถูก" — โค้ดจาก AI ต้องผ่าน test กรณีขอบก่อน
  • flowchart ไม่ตรงกับโค้ดจริง · ลืม git pull ก่อน demo
