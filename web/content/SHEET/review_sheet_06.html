🔎 DNS ทำงานอย่างไร

ถาม cache ในเครื่องก่อน → resolver (เช่น 8.8.8.8) → root → TLD (.th) → authoritative ของโดเมน → ได้ IP แล้วเก็บ cache ตาม TTL

RecordsA = IPv4 · AAAA = IPv6 · CNAME = ชื่อแฝง · MX = เมลเซิร์ฟเวอร์

⚠️ ข้อผิดพลาดที่พบบ่อย
  • คิดว่า 172.32.0.1 เป็น private (ช่วงจริงคือ 172.16–172.31 เท่านั้น)
  • ลืมลบ 2 (network + broadcast) ตอนนับ host ของ subnet
  • สับสน switch (L2, MAC) กับ router (L3, IP)
  • บอกว่า UDP "แย่กว่า" TCP — จริง ๆ แค่เหมาะกับงานต่างกัน
  • คิดว่า HTTPS = พอร์ต 80 (ที่ถูกคือ 443 และเข้ารหัสด้วย TLS)
  • ping ไม่ตอบ = เครื่องปลายทางล่มเสมอ — บางระบบบล็อก ICMP
✅ เช็กความเข้าใจ
  • วาด OSI ↔ TCP/IP พร้อม PDU ของแต่ละชั้นได้
  • อธิบายลำดับ DNS → TCP → TLS → HTTP เมื่อเปิดเว็บได้
  • เลือก TCP/UDP ให้แอปพร้อมเหตุผลได้
  • แยก private/public IP และอธิบาย NAT, DHCP ได้
  • คำนวณ mask, จำนวน host, ช่วงที่อยู่ของ /26 หรือ /27 ได้
  • ใช้ ping, nslookup, tracert แยกได้ว่าปัญหาอยู่ชั้นใด
