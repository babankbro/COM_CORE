🧩 1. นำเสนอ = พิสูจน์ด้วยหลักฐาน 4 แบบ

⚖️ 4. Trade-off ที่ควรพูดได้
Trade-offตัวอย่างการตัดสินใจของทีมเชื่อม
accuracy vs privacyนับคนที่ edge ส่งเฉพาะ "จำนวน" ไม่ส่งภาพW9, W13
cloud vs edgeedge: latency ต่ำ ประหยัด bandwidth แต่ดูแลอุปกรณ์มากขึ้นW7, W11
performance vs costMobileNetV2 เล็ก เร็ว แม่นน้อยกว่า model ใหญ่W9, W10
manual vs CI/CDลงทุนเขียน workflow ครั้งเดียว ลดความผิดพลาดทุกครั้งที่ deployW14
ความสะดวก vs ความปลอดภัยMQTT over TLS + รหัสผ่านต่ออุปกรณ์ แม้ตั้งค่ายากขึ้นW11, W12
🏗️ 5. Architecture diagram ภาพเดียวต้องมี
  • Hardware: กล้อง บอร์ด ESP32 เซนเซอร์/actuator เครื่อง server
  • Software: model, API, database, dashboard พร้อมภาษา/framework
  • Data: ลูกศรทิศทางข้อมูล + จุดที่มีข้อมูลส่วนบุคคล (ทำเครื่องหมาย)
  • Network: protocol บนลูกศร (HTTP, MQTT, Wi-Fi)
  • Security: จุดยืนยันตัวตน การเข้ารหัส และสิทธิ์การเข้าถึง
📏 6. Rubric การนำเสนอ (5 เกณฑ์ × 3 ระดับ)
เกณฑ์ดีมาก (3)พอใช้ (1)
ความถูกต้องเชิงเทคนิคหลักการถูก เชื่อมเนื้อหามีข้อผิดพลาดสำคัญ
การประยุกต์/สร้างสรรค์แก้ปัญหาจริง มีมุมใหม่ลอกแบบตรง ๆ
การสื่อสาร/นำเสนอชัดเจน ตรงเวลา สื่อดีติดขัด/ไม่ตรงเวลา
การทำงานเป็นทีมแบ่งงานชัด ทุกคนมีส่วนร่วมพึ่งบางคน
การตอบคำถามตอบลึก เข้าใจจริงตอบไม่ได้
💬 7. ตอบคำถามแบบมืออาชีพ
ฟังให้จบ → ทวนคำถาม → ตอบตรง 1 ประโยค → ยกหลักฐาน → ข้อจำกัด + ทางต่อ
คำถามที่พบบ่อยแนวตอบ
ทำไมเลือก MQTT แทน HTTP?pub/sub overhead ต่ำ เหมาะบอร์ดส่งถี่ · trade-off: งาน request/response ใช้ HTTP
model แม่นแค่ไหน?ตัวเลขจาก test set + ขนาด test set (ไม่ใช่ train accuracy)
มีประเด็น PDPA ไหม?ข้อมูลใดเป็นข้อมูลส่วนบุคคล เก็บที่ไหน นานเท่าใด ใครเข้าถึง
ขยายเป็น 50 ห้องต้องเปลี่ยนอะไร?broker, database, container, monitoring (W7, W14)
ใครทำส่วนนี้?เจ้าของส่วนตอบเอง ชี้ commit/PR ได้

ไม่รู้คำตอบ: ยอมรับ → บอกวิธีหาคำตอบ → เสนอส่งภายหลัง (ACM 1.3 ซื่อสัตย์) · ห้ามเดา

🧰 8. Checklist ก่อนขึ้นเวที
  • rehearsal จับเวลา 7–10 นาที ≥ 2 รอบ + peer feedback ตาม rubric
  • ทดสอบโปรเจกเตอร์ อินเทอร์เน็ต broker ก่อนเวลา + hotspot สำรอง
  • วิดีโอ demo สำรอง + สไลด์ backup (diagram ละเอียด ตารางผลเต็ม)
  • repo เปิดได้ README บอกวิธีรัน CI ล่าสุดผ่าน
  • แบ่งบทพูดตามงานจริง ทุกคนพร้อมตอบ
🧱 9. พูด limitation ให้เป็นมืออาชีพ
ข้อจำกัด (มีหลักฐาน) → ผลกระทบ → สาเหตุ → แนวทางแก้/แผนต่อ

"เมื่อแสงน้อยกว่าในห้องปกติ ระบบนับคนผิดบ่อยขึ้น (ทดสอบ 10 ภาพ ผิด 3 ภาพ) เพราะ dataset มีภาพกลางคืนน้อย รอบต่อไปจะเพิ่มภาพแสงน้อยและทำ data augmentation"

Presenterคุมเวลา + เปิด/ปิดเรื่อง · Demo driver คุมเครื่อง + fallback · Q&A lead รับคำถามแล้วส่งต่อเจ้าของส่วน
