🔄 1. SDLC 6 ขั้น
วิเคราะห์ requirement → ออกแบบ → พัฒนา → ทดสอบ → นำไปใช้ → บำรุงรักษา

SDLC = ขั้นตอนที่ทุกระบบต้องผ่าน · Waterfall / Agile = วิธีจัดลำดับขั้นตอนเหล่านั้น · Systems engineering = มองระบบแบบองค์รวม (requirement, architecture, integration, security, maintenance)

V-Modelทุกขั้นออกแบบจับคู่ขั้นทดสอบ (requirement ↔ acceptance test, design ↔ integration test)
Spiralวนรอบพร้อมวิเคราะห์ความเสี่ยงทุกรอบ เหมาะโครงการใหญ่/เสี่ยงสูง
Incrementalส่งมอบทีละส่วนที่ใช้งานได้ เป็นฐานของ Agile
⚖️ 2. Waterfall vs Agile vs DevOps
มิติWaterfallAgile (Scrum)DevOps
หน่วยงานphase ทั้งโครงการsprint 1–4 สัปดาห์การเปลี่ยนเล็ก ๆ ต่อเนื่อง
ส่งมอบครั้งเดียวตอนท้ายทุกสิ้น sprintได้หลายครั้งต่อวัน
requirement เปลี่ยนยาก ต้องย้อน phaseปรับ backlogfeedback จาก monitor
เหมาะกับงานมีมาตรฐานกำกับผลิตภัณฑ์ที่ต้องทดลองบริการที่รันตลอด
Scrumproduct backlog → sprint planning → build/test → review/demo → retrospective
DevOpsculture + automation + feedback + ownership ร่วม (ไม่ใช่แค่เครื่องมือ)
🚦 3. CI / CD
CImerge บ่อย + build/test อัตโนมัติทุก push/PR · ล้ม = บล็อก merge
C. Deliveryทุกเวอร์ชันที่ผ่าน CI พร้อม deploy · คนกดอนุมัติขึ้น production
C. Deploymentผ่านทุกด่าน → ขึ้น production อัตโนมัติ

ขั้นต่ำ: version control · automated build · automated test · artifact (เช่น Docker image) · deploy · rollback plan

🧠 4. MLOps / AIOps
MLOpsDevOps + version ของ data และ model · retrain · เฝ้าดู data drift/model drift
AIOpsใช้ AI วิเคราะห์ log/metric ตรวจจับความผิดปกติในงาน IT operations
🧪 5. ระดับการทดสอบ + cloud-native
ระดับทดสอบอะไรตัวอย่างในโครงงาน CV

Integrationส่วนประกอบคุยกันAPI POST /predict → บันทึกลง database
Systemทั้งระบบ end-to-endกล้อง → model → MQTT → dashboard

ContainerDocker image = environment ที่ส่งมอบซ้ำได้ ("รันเครื่องฉันได้" → รันทุกที่ได้)
Securitysecret management · image scanning · least privilege ใน pipeline
💻 6. GitHub Actions: .github/workflows/ci.yml
name: CI on: [push, pull_request] # ทริกเกอร์ทุก push และ PR jobs: test: runs-on: ubuntu-latest # runner ของ GitHub steps: - uses: actions/checkout@v4 # ดึงโค้ดจาก repo - uses: actions/setup-python@v5 with: python-version: "3.11" - run: pip install -r requirements.txt - run: flake8 . # lint - run: pytest -q # unit test ล้ม = ❌

workflow → jobs → steps · uses = action สำเร็จรูป · run = คำสั่ง shell · ไม่ใส่ model ไฟล์ใหญ่และ secret ลงใน repo (ใช้ GitHub Secrets)

🌿 7. Git workflow ของหนึ่งฟีเจอร์
git switch -c feature/42-show-confidence # แยก branch git add . && git commit -m "feat: return confidence (#42)" git push -u origin feature/42-show-confidence # แล้วเปิด PR git tag v1.2.0 && git push --tags # release
issue → branch → commit → PR → CI ✓ → review → merge → deploy → monitor

⚠️ ข้อผิดพลาดที่พบบ่อย
  • คิดว่า DevOps = เครื่องมือ deploy อย่างเดียว (ลืมวัฒนธรรม/feedback)
  • สับสน Continuous Delivery (รออนุมัติ) กับ Continuous Deployment (อัตโนมัติ)
  • ทำงานบน main ตรง ๆ ไม่ผ่าน PR/review
  • merge ทั้งที่ CI แดง · ไม่มี rollback plan
  • acceptance criteria วัดไม่ได้ เช่น "ใช้งานง่าย"
  • commit secret/API key หรือไฟล์ model ขนาดใหญ่เข้า repo

  • เล่าเส้นทาง issue → PR → CI → deploy ของหนึ่งฟีเจอร์
  • เขียน user story + acceptance criteria ที่ตรวจได้
