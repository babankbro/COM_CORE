🗄️ 1. คำศัพท์หลักของ Relational Database
DBMSตัวกลางระหว่างแอปกับข้อมูล (เหมือนบรรณารักษ์): ตรวจกฎ จัด index คุมผู้ใช้พร้อมกัน · SQLite, MySQL, PostgreSQL
Tablerelation · แถว = record (tuple) · คอลัมน์ = attribute · schema = โครงสร้างตาราง
Primary Keyระบุแถวไม่ซ้ำ ห้าม NULL · มีได้ 1 ชุดต่อตาราง (อาจเป็น PK ผสมหลายคอลัมน์)
Foreign Keyคอลัมน์ที่อ้าง PK ของอีกตาราง → referential integrity · ซ้ำได้
ER Diagramออกแบบระดับแนวคิด: entity · attribute · relationship (1:1, 1:N, M:N)
Indexสารบัญ (B-tree) ค้นเร็ว O(log n) แลกกับเขียนช้าลงและใช้พื้นที่เพิ่ม
🔗 2. ER → ตาราง: M:N ต้องมีตารางเชื่อม
ความสัมพันธ์ตัวอย่างวิธีเก็บ
1:1นักศึกษา–บัตรนักศึกษาFK แบบ UNIQUE ฝั่งใดฝั่งหนึ่ง
1:NCategory–Asset, คณะ–นักศึกษาFK อยู่ฝั่ง N
M:NStudent–Courseตารางเชื่อม Enrollment FK 2 ตัว
🧹 3. Normalization (ข้อมูลแต่ละเรื่องอยู่ที่เดียว)
ระดับเงื่อนไขตัวอย่างที่ผิด
1NFทุกช่องค่าเดียว (atomic) ไม่มีกลุ่มซ้ำcourses = "MA101, PG101"
2NF1NF + ไม่มี partial dependency กับ PK ผสมcourse_title ขึ้นกับ course_id ส่วนเดียว
3NF2NF + ไม่มี transitive (non-key → non-key)major_id → major_name ในตาราง Student

"the key (1NF), the whole key (2NF), and nothing but the key (3NF)" · แก้ update / insert / delete anomaly

🏦 4. ACID (โอนเงิน 500 บาท A → B)
Atomicityครบทั้งหมดหรือไม่ทำเลย: หัก A แล้วไฟดับ → rollback
Consistencyไม่ผิดกฎ (CHECK, FK) ยอดห้ามติดลบ เงินรวมเท่าเดิม
Isolationธุรกรรมพร้อมกันได้ผลเหมือนทำทีละรายการ
Durabilitycommit แล้วไม่หาย แม้ระบบล่ม

Python + SQLite: INSERT/UPDATE/DELETE ไม่ถาวรจนกว่าจะ conn.commit() · ยกเลิกด้วย conn.rollback()

⚙️ 6. ลำดับประมวลผล SQL (ไม่ใช่ลำดับที่เขียน)
FROM/JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
SELECT faculty, COUNT(*) AS n, ROUND(AVG(gpa), 2) AS avg_gpa FROM students -- 15 แถว WHERE gpa >= 3.0 -- กรองแถว → 10 แถว GROUP BY faculty -- 3 กลุ่ม HAVING COUNT(*) >= 3 -- กรองกลุ่ม → 3 กลุ่ม ORDER BY avg_gpa DESC LIMIT 2; -- วิทยาศาสตร์ 3 คน 3.68 · วิศวกรรมศาสตร์ 4 คน 3.49
WHEREHAVING
กรองแถวก่อนจัดกลุ่ม · ใช้ aggregate ไม่ได้กรองกลุ่มหลัง GROUP BY · ใช้ COUNT/AVG ได้

🐍 8. Python + SQLite (Lab 05)
import sqlite3, pandas as pd conn = sqlite3.connect("students.db") conn.execute("PRAGMA foreign_keys = ON") # SQLite ต้องเปิดตรวจ FK เอง df = pd.read_csv("student.csv", dtype={"student_id": str}) df.to_sql("students", conn, if_exists="replace", index=False) pd.read_sql_query("SELECT * FROM students WHERE faculty = ?", conn, params=("วิทยาศาสตร์",)) # → DataFrame cur = conn.cursor() cur.execute("SELECT * FROM students WHERE gpa > ?", (3.5,)) rows = cur.fetchall() # list ของ tuple conn.commit() # หลัง INSERT/UPDATE/DELETE

if_exists: fail (ค่าเริ่มต้น) · replace (DROP แล้วสร้างใหม่ → PK/FK หาย) · append (รันซ้ำ = ข้อมูลซ้ำ)

⚠️ ข้อผิดพลาดที่พบบ่อย
  • ต่อสตริง/f-string ใส่ค่าจากผู้ใช้ → SQL injection (x' OR '1'='1 ได้ทั้ง 15 แถว) ต้องใช้ ?
  • UPDATE/DELETE ลืม WHERE → แก้/ลบทุกแถว
  • ลืม conn.commit() → ปิดโปรแกรมแล้วข้อมูลหาย
  • ใช้ WHERE AVG(gpa) > 3 → ต้องเป็น HAVING
  • เก็บ M:N ด้วยคอลัมน์รายการคั่นจุลภาค (ผิด 1NF) แทนตารางเชื่อม
  • คิดว่า SQLite ตรวจ FK อัตโนมัติ — ต้อง PRAGMA foreign_keys = ON
  • เก็บข้อมูลส่วนบุคคลเกินจำเป็น / ไม่ขอความยินยอม → ขัด PDPA
✅ เช็กความเข้าใจ
  • อธิบาย PK, FK, PK ผสม และวาด ER ระบบเล็ก ๆ ที่มี M:N ได้
  • ระบุว่าตารางผิด 1NF/2NF/3NF ข้อใดและแยกตารางแก้ได้
  • อธิบาย ACID ด้วยตัวอย่างโอนเงินได้
  • เขียน SELECT + WHERE + GROUP BY + HAVING + ORDER BY + JOIN ได้ และบอกลำดับประมวลผล
  • ใช้ sqlite3 + placeholder ? + commit() ได้ถูกต้อง
  • เลือก SQL / NoSQL / Vector DB ให้เหมาะกับโจทย์ และอธิบาย keyword vs semantic search ได้
