🧱 1. ชั้นของระบบ
ผู้ใช้ → Application → Library/Runtime → OS kernel → Driver → Firmware → Hardware
HardwareCPU, GPU/NPU, RAM, storage (SSD/HDD), I/O, bus — ทรัพยากรกายภาพ
Firmwareโปรแกรมฝังในอุปกรณ์ เช่น UEFI/BIOS, firmware ใน SSD
OSตัวกลางจัดการ process · memory · file · device และความปลอดภัย
Driverซอฟต์แวร์ที่ "แปลภาษา" ให้ OS สั่งอุปกรณ์แต่ละรุ่นได้
System callช่องทางที่โปรแกรมขอบริการจาก OS (user mode → kernel mode) เช่น open, write

ซอฟต์แวร์ระบบ (OS, driver, utility) vs ซอฟต์แวร์ประยุกต์ (เกม เบราว์เซอร์) · open source vs proprietary ต่างกันที่สัญญาอนุญาต

🗄️ 2. Memory hierarchy (เร็ว–แพง–เล็ก → ช้า–ถูก–ใหญ่)
ชั้นlatency โดยประมาณขนาดทั่วไปไฟดับ
Register~0.3 nsไม่กี่ร้อยไบต์หาย (volatile)
Cache L1/L2/L3~1 / 4 / 15 nsKB – สิบ MB
RAM (DRAM)~100 ns8–64 GB
SSD (NVMe)~100 µs0.5–4 TBอยู่ (non-volatile)
HDD~10 ms1–20 TB
1 ms = 1,000 µs = 1,000,000 ns · RAM ≈ 100× ช้ากว่า L1 · SSD ≈ 1,000× ช้ากว่า RAM
  • Locality: temporal (เพิ่งใช้ จะใช้อีก) · spatial (อยู่ติดกัน จะใช้ต่อ) → cache ดึงเป็น cache line
  • RAM ไม่พอ → OS ย้ายหน้าไป swap/page file บน SSD → เครื่องช้าลงชัดเจน
  • Virtual memory + MMU: แต่ละ process เห็นพื้นที่ของตัวเอง แปลงที่อยู่เสมือนเป็นที่อยู่จริง
⚙️ 3. CPU · GPU · NPU (Heterogeneous computing)
หน่วยโครงสร้างเหมาะกับ
CPUคอร์ใหญ่ไม่กี่คอร์ + cache ใหญ่งานทั่วไป ลำดับซับซ้อน OS ลอจิกเกม
GPUคอร์เล็กหลายพันคอร์งานขนาน กราฟิก train โมเดล
NPUอาร์เรย์คูณ-บวก (MAC)AI inference บนอุปกรณ์ ประหยัดไฟ

เปรียบ: CPU = เชฟมือหนึ่งไม่กี่คน · GPU = พนักงานหั่นผักหลายพันคน · NPU = เครื่องจักรสายพานที่ทำงานเดียว · SoC = รวม CPU+GPU+NPU+ตัวควบคุมหน่วยความจำไว้บนชิปเดียว (มือถือ, Apple M-series) · logical CPU อาจ = 2 × คอร์จริงเมื่อมี SMT

🚶 4. ตามรอยการทำงาน: กด Save / เปิดโปรแกรม
  1. App แปลงสถานะเกมเป็น JSON แล้วเรียก open()/write() → runtime พักข้อมูลใน buffer
  2. System call (write บน Linux, WriteFile บน Windows) → CPU สลับเข้า kernel mode
  3. OS ระบบไฟล์หาบล็อกบนดิสก์ อาจพักใน page cache บน RAM → driver ส่งคำสั่ง NVMe
  4. Firmware SSD เลือกเซลล์ flash แล้วเขียน (non-volatile) → ผลสำเร็จ/ผิดพลาดย้อนกลับขึ้นไปที่ app

เปิดโปรแกรม: OS โหลดไฟล์โปรแกรมจาก storage → RAM สร้าง process (PID, พื้นที่หน่วยความจำ) → scheduler แบ่งเวลา CPU → คำสั่ง/ข้อมูลที่ใช้บ่อยขึ้นไปอยู่ใน cache

📡 5. Edge vs Cloud · Container
ประเด็นCloudEdge
ที่ประมวลผลdata center ระยะไกลใกล้แหล่งข้อมูล (กล้อง เกตเวย์ มือถือ)
Latencyสูงกว่า (ไป-กลับเครือข่าย)ต่ำ ตอบสนองทันที
พลังประมวลผลสูง ขยายได้จำกัดด้วยพลังงาน/ความร้อน
ความเป็นส่วนตัวข้อมูลดิบออกจากเครื่องส่งเฉพาะผลสรุปได้
Containerแพ็กแอป + library ใช้ kernel ร่วมกับ host (namespaces + cgroups) เบาและเริ่มเร็วกว่า VM
VMจำลองเครื่องทั้งเครื่องผ่าน hypervisor มี OS ของตัวเอง แยกขาดกว่าแต่หนักกว่า
🌱 6. Green computing
PUE = พลังงานรวมของ data center ÷ พลังงานที่อุปกรณ์ IT ใช้  (ค่าดีสุด = 1.0)

ตัวอย่าง: ใช้รวม 1,500 kW, IT ใช้ 1,000 kW → PUE = 1.5 (อีก 500 kW ไปกับระบบทำความเย็น/ไฟฟ้า)

ออกแบบประหยัดพลังงานตั้งแต่ต้น: เลือก HW ให้พอดีงาน, sleep mode, ลดการส่งข้อมูล, liquid cooling

⚠️ ข้อผิดพลาดที่พบบ่อย
  • สับสน RAM (หน่วยความจำหลัก ลบเลือน) กับ storage (เก็บถาวร) — "ความจุ 512 GB" มักหมายถึง SSD
  • คิดว่า GPU/NPU มาแทน CPU — จริง ๆ เป็นตัวเร่งงานเฉพาะ CPU ยังคุมลำดับงานและ OS
  • นับ os.cpu_count() เป็นจำนวนคอร์จริง (คือ logical CPU)
  • สับสน GB (10⁹) กับ GiB (2³⁰ = 1,073,741,824 bytes) ทำให้ตัวเลขดิสก์ "หาย"
  • เปิดไฟล์โดยไม่ปิด/ไม่ใช้ with → ข้อมูลค้างใน buffer ไฟล์ save ไม่ครบ
  • คิดว่า edge ดีกว่า cloud เสมอ — edge แลกกับการอัปเดตและดูแลความปลอดภัยอุปกรณ์จำนวนมาก
✅ เช็กความเข้าใจ
  • เรียงชั้น application → hardware และอธิบายหน้าที่ของ OS 4 อย่างได้
  • ตามรอยคำสั่ง Save ผ่าน system call, driver, firmware ได้
  • เรียง memory hierarchy จากเร็วไปช้า พร้อมเหตุผลเรื่องราคา/ขนาด/locality ได้
  • เลือก CPU/GPU/NPU ให้เหมาะกับงานตัวอย่างได้
  • อธิบายว่า edge ลด latency อย่างไร และคำนวณ PUE ได้
  • เขียนสคริปต์รายงานสเปกเครื่องด้วย platform/psutil ได้
✍️ ฝึกคิด (เฉลยท้ายกล่อง)
  1. Data center ใช้ไฟรวม 2,400 kW อุปกรณ์ IT ใช้ 1,600 kW → PUE = ?
  2. ถ้า 1 ns = 1 วินาที การอ่าน RAM (~100 ns) และ SSD (~100 µs) นานเท่าใด?
  3. กล้องในโรงงานต้องหยุดสายพานภายใน 20 ms เมื่อพบคนเข้าเขตอันตราย ควรประมวลผลที่ edge หรือ cloud?
  4. งานแปลงวิดีโอ 4K เป็นเฟรม ๆ พร้อมกันจำนวนมาก ควรใช้ CPU, GPU หรือ NPU?

เฉลย: (1) 2,400 ÷ 1,600 = 1.5 · (2) ~100 วินาที (≈ 1.7 นาที) และ 100,000 วินาที (≈ 1.2 วัน) · (3) edge — ไม่ต้องรอเครือข่ายไป-กลับ · (4) GPU — งานขนานแบบเดียวกันจำนวนมาก
