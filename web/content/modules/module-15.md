ยินดีต้อนรับสู่สัปดาห์ที่ 15 ซึ่งเป็นสัปดาห์สำคัญที่จะเชื่อมโยงความรู้ทางทฤษฎีที่ได้ศึกษามาตลอดภาคการศึกษา เข้ากับโลกแห่งความเป็นจริงในอุตสาหกรรมคอมพิวเตอร์และเทคโนโลยีสารสนเทศ การดูงานเชิงวิชาการ (Academic and Industrial Field Trip) ถือเป็นกลไกสำคัญที่จะช่วยให้นักศึกษาเกิดความเข้าใจอย่างลึกซึ้งถึงกระบวนการทำงานจริง สภาพแวดล้อมทางธุรกิจ และความท้าทายที่วิศวกรคอมพิวเตอร์ต้องเผชิญ

ในสัปดาห์นี้ เราจะมุ่งเน้นไปที่การเปิดโลกทัศน์และเตรียมความพร้อมสู่การเป็นบัณฑิตที่มีคุณภาพ โดยแบ่งเนื้อหาออกเป็น 5 ส่วนหลัก ได้แก่:
1. **ภาพรวมอุตสาหกรรมคอมพิวเตอร์และศูนย์ข้อมูล (Data Center):** ทำความเข้าใจโครงสร้างพื้นฐานระดับองค์กรขนาดใหญ่
2. **การเตรียมความพร้อมสู่การทำงานจริง:** ทักษะทางอารมณ์และสังคม (Soft Skills) และการปรับตัวในองค์กร
3. **การทัศนศึกษาเสมือนจริง (Virtual Field Trip):** เปิดประสบการณ์การทำงานในบริษัทเทคโนโลยีชั้นนำระดับโลก
4. **บทบาทอาชีพและทักษะวิศวกรคอมพิวเตอร์ยุคใหม่:** สำรวจสายงานต่างๆ เช่น Data Engineer, Cloud Architect และ DevOps
5. **การจัดทำรายงานและการประยุกต์ใช้ความรู้:** การสรุปองค์ความรู้และการนำเสนออย่างมืออาชีพ

เป้าหมายสูงสุดของสัปดาห์นี้คือการกระตุ้นให้นักศึกษาเกิดแรงบันดาลใจ มองเห็นภาพเส้นทางอาชีพของตนเองอย่างชัดเจน และสามารถบูรณาการความรู้ทางวิศวกรรมคอมพิวเตอร์เพื่อสร้างสรรค์นวัตกรรมที่ตอบโจทย์ความต้องการของภาคอุตสาหกรรมและสังคมได้อย่างแท้จริง

## คำถามนำ
เมื่อเห็นระบบจริงในอุตสาหกรรม เราควรสังเกตอะไรให้เชื่อมกับความรู้รายวิชา?

## ผลลัพธ์การเรียนรู้ย่อย
1. เตรียมคำถามและกรอบสังเกตสำหรับ site visit
2. เชื่อมเทคโนโลยีจริงกับหัวข้อรายสัปดาห์
3. ฝึกเขียนรายงานเชิงวิชาชีพและคำนึงถึงข้อมูลลับ/PDPA

## แก่นความรู้ที่ต้องเข้าใจ
- การดูงานไม่ใช่การไปเยี่ยมชมอย่างเดียว แต่เป็นการเก็บหลักฐานการเรียนรู้จากระบบจริง
- ผู้เรียนควรสังเกต technology stack, workflow, role ของคน, security, reliability และ sustainability
- การถ่ายภาพหรือบันทึกข้อมูลต้องเคารพกฎองค์กร ความลับ และข้อมูลส่วนบุคคล

## เนื้อหาเรียนรู้
- ก่อนดูงาน ให้ผู้เรียนเตรียม checklist ตาม 6 มุม: hardware, software, data, network, security, people/process
- ระหว่างดูงาน ให้จดสิ่งที่เห็นเป็น evidence ไม่ใช่ความรู้สึก เช่นเห็น rack, dashboard, access control, ticket workflow หรือ pipeline
- หลังดูงาน ให้เขียน reflection เชื่อมอย่างน้อย 3 สัปดาห์ของรายวิชา เช่น data center กับ PUE, IoT กับ MQTT, security กับ Zero Trust

## 🧭 อธิบายเพิ่มเติม (ฉบับขยาย)

### 1) มองอุตสาหกรรมเป็นห่วงโซ่ ไม่ใช่บริษัทเดี่ยว
แอปที่เราใช้ทุกวันเหมือนอาหารหนึ่งจาน กว่าจะมาถึงโต๊ะต้องผ่านเกษตรกร โรงงานแปรรูป รถขนส่ง และร้านอาหาร อุตสาหกรรมคอมพิวเตอร์ก็เช่นกัน มีตั้งแต่ชั้น semiconductor ที่ผลิตชิป, ชั้น hardware/electronics ที่ประกอบแผงวงจรและเซิร์ฟเวอร์, ชั้น cloud/data center ที่ให้ไฟฟ้า ระบบเย็น และพลังประมวลผล, ชั้น software/platform และชั้น services ที่ผู้ใช้สัมผัส เมื่อไปดูงานที่ใด ให้ถามก่อนว่า "หน่วยงานนี้อยู่ชั้นไหน และส่งคุณค่าต่อให้ใคร"

![ห่วงโซ่คุณค่าอุตสาหกรรมคอมพิวเตอร์ 5 ชั้น จาก semiconductor, hardware/electronics, cloud/data center, software/platform ถึง services/apps พร้อมงานของวิศวกรคอมพิวเตอร์และสัปดาห์ที่เชื่อมโยง](/images/weeks/w15-value-chain.svg)

### 2) สังเกตแบบนักวิจัย: evidence ไม่ใช่ความรู้สึก
การดูงานคล้ายการเป็นนักสืบ นักสืบไม่จดว่า "ห้องนี้น่ากลัว" แต่จดว่า "ประตูมีเครื่องสแกนลายนิ้วมือ 2 ชั้น" รายงานที่ดีจึงแยก 3 อย่างออกจากกัน:
- **Evidence (สิ่งที่เห็น/ได้ยิน):** "rack แต่ละตู้มีป้ายบอก hot aisle และ cold aisle"
- **Interpretation (การตีความโดยอิงหลักการ):** "การแยกทางลมร้อน/เย็นช่วยลดพลังงานระบบเย็น ซึ่งส่งผลต่อค่า PUE (W7)"
- **Opinion (ความเห็น):** "ประทับใจความเป็นระเบียบ" ใส่ได้ แต่ต้องไม่แทนที่ evidence

![กรอบสังเกต 6 มุมรอบการดูงาน ได้แก่ hardware, software, data, network, security และ people/process แต่ละมุมมีคำถามนำ ตัวอย่างหลักฐาน และสัปดาห์ที่เชื่อมโยง](/images/weeks/w15-observation-lenses.svg)

### 3) ตัวอย่าง: mapping หลักฐานจากการดูงานศูนย์ข้อมูลสู่รายวิชา
สมมติผู้เรียนทัศนศึกษาเสมือนจริงศูนย์ข้อมูลของผู้ให้บริการ cloud แล้วจด field note ดังนี้

| หลักฐานที่บันทึก (evidence) | มุมสังเกต | เชื่อมหัวข้อ/สัปดาห์ | การตีความ | CLO |
|---|---|---|---|---|
| ผู้บรรยายบอกว่าค่า PUE เฉลี่ยของไซต์อยู่ราว 1.1 | Hardware | W7 PUE | พลังงานเกือบทั้งหมดไปที่อุปกรณ์ IT ระบบเย็นมีประสิทธิภาพ | CLO4 |
| ทางเข้ามีหลายชั้น: บัตร + biometric + เจ้าหน้าที่ | Security | W12 defense-in-depth | ป้องกันซ้อนหลายชั้น ไม่พึ่งจุดเดียว | CLO4 |
| ฮาร์ดดิสก์ที่เลิกใช้ถูกทำลายในพื้นที่ | Data | W12 CIA, W13 PDPA | ป้องกันการรั่วของข้อมูลส่วนบุคคลหลังหมดอายุอุปกรณ์ | CLO5 |
| ข้อมูลถูกสำเนาข้ามหลายโซน | Data / Network | W5, W6, W7 | เพิ่ม availability เมื่อไซต์หนึ่งล่ม | CLO4 |
| ทีม operations ทำงาน 24/7 มี change process | People / Process | W14 DevOps/SRE | การเปลี่ยนระบบต้องมีขั้นตอนและบันทึก | CLO6 |

สังเกตว่าแต่ละแถวมี "สิ่งที่เห็นจริง" อยู่ก่อน แล้วจึงโยงหลักการ และรายงานต้องเชื่อมอย่างน้อย 3 หัวข้อ (ระบุสัปดาห์) ตามโครงร่างรายงานการดูงาน ตัวเลขที่ได้ยินจากวิทยากรให้ระบุแหล่ง ("ตามที่วิทยากรกล่าว") และอย่าแต่งตัวเลขเพิ่มเอง

### 4) จรรยาบรรณระหว่างดูงาน: ความลับ + PDPA
- ถามก่อนถ่ายภาพทุกครั้ง หลายพื้นที่ห้ามถ่าย rack, หน้าจอ dashboard หรือแผนผังอาคาร เพราะเป็นข้อมูลที่ใช้วางแผนโจมตีได้ (Confidentiality ใน CIA)
- ภาพที่มีหน้าคนหรือชื่อบนบัตรพนักงานเป็นข้อมูลส่วนบุคคล ให้เบลอหรือไม่ใช้
- ห้ามถามข้อมูลลูกค้า ราคาสัญญา หรือช่องโหว่ระบบ ให้ถามเชิงหลักการแทน เช่น "ทีมตัดสินใจเรื่อง redundancy อย่างไร"
- ถ้าใช้ AI ช่วยเรียบเรียงรายงาน ต้องเปิดเผยการใช้และตรวจข้อเท็จจริงเอง (เชื่อม W13)

### 5) ตัวอย่างคำถามดีกับวิทยากร
| ควรถาม | ไม่ควรถาม | เหตุผล |
|---|---|---|
| ทักษะใดที่นักศึกษาปี 1 ควรเริ่มฝึก | เงินเดือนของพนักงานแต่ละคน | ข้อมูลส่วนบุคคล/ไม่เกี่ยวกับการเรียนรู้ |
| ทีมวัดความน่าเชื่อถือของระบบด้วย metric อะไร | ระบบเคยถูกเจาะผ่านช่องโหว่ไหน | ข้อมูลความปลอดภัยที่เป็นความลับ |
| มีแนวทางลดพลังงานระบบเย็นอย่างไร | ลูกค้ารายใหญ่ของบริษัทคือใคร | ความลับทางการค้า |

![แผนภาพจับคู่บทบาทอาชีพวิศวกรคอมพิวเตอร์ เช่น embedded, IoT, network, cloud, DevOps/SRE, data, ML และ security engineer กับสัปดาห์ของรายวิชาที่ใช้ความรู้นั้น](/images/weeks/w15-career-roles.svg)

6. ภาพประกอบ (ตามที่หน่วยงานอนุญาต — คำนึงถึง [ความลับข้อมูล](/concept/cia-triad) และ [PDPA](/concept/pdpa))

### ❓ คำถามนำสังเกต (เตรียมก่อนไป)
- หน่วยงานใช้เทคโนโลยีใดที่ตรงกับหัวข้อที่เรียน
- ตำแหน่งงานด้านคอมพิวเตอร์มีอะไรบ้าง ใช้ทักษะใด
- ความท้าทายด้านความปลอดภัย/พลังงาน/ข้อมูลขององค์กรคืออะไร
