การเปลี่ยนผ่านสู่คลาวด์คอมพิวติ้ง (Cloud Computing) ทำให้องค์กรมีตัวเลือกในการนำไปใช้งาน (Deployment Models) ที่หลากหลาย เพื่อให้ตอบสนองต่อความต้องการด้านต้นทุน ความปลอดภัย และกฎหมายที่แตกต่างกัน ในหัวข้อนี้เราจะทำความเข้าใจ 3 รูปแบบหลัก ได้แก่ Public Cloud, Private Cloud และ Sovereign Cloud

## 1. Public Cloud (คลาวด์สาธารณะ)
Public Cloud คือบริการคลาวด์ที่ให้บริการโดยผู้ให้บริการบุคคลที่สาม (Third-Party Cloud Providers) เช่น Amazon Web Services (AWS), Microsoft Azure และ Google Cloud Platform (GCP) 

**ลักษณะเด่น:**
- **Shared Infrastructure:** ทรัพยากรฮาร์ดแวร์ถูกใช้งานร่วมกันระหว่างผู้ใช้บริการหลายราย (Multi-tenant)
- **Pay-as-you-go:** จ่ายเงินเฉพาะตามปริมาณการใช้งานจริง หมดปัญหาการลงทุนล่วงหน้า (CapEx)
- **High Scalability:** สามารถขยายทรัพยากรได้อย่างไร้ขีดจำกัดภายในระยะเวลาอันสั้น

*ข้อควรระวัง:* องค์กรไม่สามารถควบคุมตำแหน่งทางกายภาพที่จัดเก็บข้อมูลได้อย่างสมบูรณ์ และมีข้อกังวลด้านความปลอดภัยเมื่อเทียบกับ Private Cloud

## 2. Private Cloud (คลาวด์ส่วนตัว)
Private Cloud คือสภาพแวดล้อมคลาวด์ที่ถูกสร้างและสงวนไว้สำหรับใช้งานภายในองค์กรเดียวเท่านั้น อาจตั้งอยู่ในศูนย์ข้อมูล (On-premise Data Center) ขององค์กรเอง หรือเช่าศูนย์ข้อมูลภายนอกแบบ Co-location

**ลักษณะเด่น:**
- **Exclusive Use:** ทรัพยากรถูกใช้งานโดยองค์กรเดียว (Single-tenant) ไม่มีการแชร์ร่วมกับผู้อื่น
- **High Security & Control:** องค์กรมีอำนาจในการจัดการเครือข่ายความปลอดภัยและฮาร์ดแวร์แบบเบ็ดเสร็จ
- **Customization:** สามารถปรับแต่งสถาปัตยกรรมให้ตรงกับแอปพลิเคชันเฉพาะทาง (Legacy Systems) ได้

*ความท้าทาย:* องค์กรต้องแบกรับต้นทุนในการซื้อและบำรุงรักษาฮาร์ดแวร์เอง รวมถึงต้องมีทีมผู้เชี่ยวชาญในการดูแลระบบ

## 3. Sovereign Cloud (คลาวด์อธิปไตย)
Sovereign Cloud เป็นแนวคิดที่เกิดขึ้นจากข้อกังวลด้านความมั่นคงระดับชาติ กฎหมายคุ้มครองข้อมูลส่วนบุคคล (เช่น GDPR ของยุโรป หรือ PDPA ของไทย) และการผูกขาดทางเทคโนโลยีของบริษัทยักษ์ใหญ่ข้ามชาติ

**ลักษณะเด่น:**
- **Data Sovereignty:** ข้อมูลจะต้องถูกจัดเก็บ ประมวลผล และบริหารจัดการภายใต้ขอบเขตพรมแดนและกฎหมายของประเทศนั้นๆ
- **Local Operation:** ผู้ให้บริการต้องเป็นบริษัทภายในประเทศ หรือหน่วยงานภาครัฐ เพื่อป้องกันไม่ให้รัฐบาลต่างชาติเข้าถึงข้อมูลได้
- **Compliance:** ตอบโจทย์ข้อบังคับด้านความมั่นคงของข้อมูลในอุตสาหกรรมที่มีความอ่อนไหวสูง เช่น การแพทย์ การเงิน และหน่วยงานความมั่นคง

## บทสรุปเปรียบเทียบ

| คุณสมบัติ | Public Cloud | Private Cloud | Sovereign Cloud |
| :--- | :--- | :--- | :--- |
| **ความเป็นเจ้าของฮาร์ดแวร์** | ผู้ให้บริการระดับโลก | องค์กร | หน่วยงานในประเทศ/รัฐ |
| **ระดับความปลอดภัย/การควบคุม** | ปานกลาง - สูง | สูงมาก | สูงมากที่สุด (ระดับชาติ) |
| **ต้นทุนการเริ่มต้น** | ต่ำ (จ่ายตามจริง) | สูง (ต้องซื้อฮาร์ดแวร์) | ปานกลาง - สูง |
| **ความยืดหยุ่น (Scalability)**| สูงที่สุด | จำกัดตามฮาร์ดแวร์ที่มี | ขึ้นอยู่กับผู้ให้บริการในประเทศ |

การเลือกใช้คลาวด์มักลงเอยในรูปแบบ **Hybrid Cloud** หรือ **Multi-Cloud** เพื่อดึงข้อดีของคลาวด์แต่ละประเภทมาประยุกต์ใช้ร่วมกันอย่างมีประสิทธิภาพสูงสุด

## รูปแบบบริการ IaaS / PaaS / SaaS (Cloud Service Models)

หัวข้อก่อนหน้าคือ **Deployment Models** (คลาวด์ตั้งอยู่ที่ไหน ใครเป็นเจ้าของ) ส่วนหัวข้อนี้คือ **Service Models** ซึ่งตอบคำถามว่า "ผู้ให้บริการจัดการให้ถึงระดับไหน และเราต้องจัดการเองแค่ไหน" แบ่งเป็น 3 ระดับหลักตามนิยามของ NIST

### 1. IaaS (Infrastructure as a Service)
เช่า **โครงสร้างพื้นฐาน** ได้แก่ เครื่องเสมือน (VM) พื้นที่จัดเก็บ และเครือข่าย จากนั้น **เราติดตั้งระบบปฏิบัติการ ซอฟต์แวร์ และแอปพลิเคชันเอง**
- ตัวอย่าง: **Amazon EC2**, **Google Compute Engine**, **Azure Virtual Machines**
- เหมาะกับ: ผู้ที่ต้องการควบคุมระบบเต็มที่ เช่น ติดตั้ง Ubuntu + ฐานข้อมูล + เว็บเซิร์ฟเวอร์เอง

### 2. PaaS (Platform as a Service)
ผู้ให้บริการเตรียม **แพลตฟอร์มสำหรับรันโค้ด** ไว้ให้ครบ (OS, Runtime, การ Scale) เรา **อัปโหลดเฉพาะโค้ดและข้อมูล** ของเรา
- ตัวอย่าง: **Google App Engine**, **Vercel**, **Heroku**, Render, Azure App Service
- เหมาะกับ: นักพัฒนาที่อยากโฟกัสที่การเขียนโค้ด ไม่อยากดูแลเซิร์ฟเวอร์

### 3. SaaS (Software as a Service)
ใช้ **ซอฟต์แวร์สำเร็จรูป** ผ่านเว็บเบราว์เซอร์หรือแอป ผู้ให้บริการดูแลทั้งหมด เราเพียงใช้งานและดูแลข้อมูลของเราเอง
- ตัวอย่าง: **Gmail**, **Google Docs**, **Microsoft 365**, **Canva**, Zoom
- เหมาะกับ: ผู้ใช้ทั่วไปและองค์กรที่ต้องการใช้งานทันที

### ตาราง Shared Responsibility: ใครจัดการอะไร

| ชั้นของระบบ | On-premises (ทำเองทั้งหมด) | IaaS | PaaS | SaaS |
| :--- | :---: | :---: | :---: | :---: |
| ข้อมูล (Data) และสิทธิ์ผู้ใช้ | **ผู้ใช้** | **ผู้ใช้** | **ผู้ใช้** | **ผู้ใช้** |
| แอปพลิเคชัน (Application) | **ผู้ใช้** | **ผู้ใช้** | **ผู้ใช้** | ผู้ให้บริการ |
| Runtime / Middleware | **ผู้ใช้** | **ผู้ใช้** | ผู้ให้บริการ | ผู้ให้บริการ |
| ระบบปฏิบัติการ (OS) | **ผู้ใช้** | **ผู้ใช้** | ผู้ให้บริการ | ผู้ให้บริการ |
| Virtualization | **ผู้ใช้** | ผู้ให้บริการ | ผู้ให้บริการ | ผู้ให้บริการ |
| เซิร์ฟเวอร์ / Storage / Network | **ผู้ใช้** | ผู้ให้บริการ | ผู้ให้บริการ | ผู้ให้บริการ |
| อาคาร ไฟฟ้า ระบบทำความเย็น | **ผู้ใช้** | ผู้ให้บริการ | ผู้ให้บริการ | ผู้ให้บริการ |

> [!warning] ข้อมูลเป็นความรับผิดชอบของเราเสมอ
> แม้จะใช้ SaaS ผู้ใช้ยังต้องรับผิดชอบเรื่องการตั้งรหัสผ่าน การกำหนดสิทธิ์การแชร์ไฟล์ และการปฏิบัติตามกฎหมายคุ้มครองข้อมูล เช่น [PDPA](/concept/pdpa)

### อุปมา "Pizza as a Service"

| รูปแบบ | เปรียบกับพิซซ่า | เราทำเอง | ร้านทำให้ |
| :--- | :--- | :--- | :--- |
| **On-premises** | ทำพิซซ่าเองที่บ้าน | แป้ง ซอส ท็อปปิ้ง เตาอบ แก๊ส โต๊ะ | — |
| **IaaS** | เช่าครัวพร้อมเตาอบ | แป้ง ซอส ท็อปปิ้ง และลงมืออบเอง | สถานที่ เตาอบ แก๊ส |
| **PaaS** | ซื้อพิซซ่าแช่แข็ง/สั่ง Delivery มากินที่บ้าน | จัดโต๊ะ เครื่องดื่ม (เตรียมแค่ส่วนของเรา) | แป้ง ซอส ท็อปปิ้ง การอบ |
| **SaaS** | ไปกินที่ร้านอาหาร | แค่กิน (ใช้งาน) | ทุกอย่าง |

> [!tip] วิธีจำแบบนักศึกษา
> - **IaaS** = ได้ "เครื่องเปล่า" ต้องลง OS และโปรแกรมเอง
> - **PaaS** = ได้ "ที่วางโค้ด" แค่ `git push` แอปก็ออนไลน์
> - **SaaS** = ได้ "โปรแกรมพร้อมใช้" เปิดเบราว์เซอร์ก็ใช้ได้เลย

<details><summary>แบบฝึกหัด: บริการต่อไปนี้เป็นแบบใด (คลิกดูเฉลย)</summary>

1. นักศึกษาเช่า Amazon EC2 แล้วติดตั้ง Ubuntu, Nginx และ MySQL เอง — **IaaS**
2. ทีมอัปโหลดโค้ด Next.js ขึ้น Vercel แล้วได้ URL ทันที — **PaaS**
3. อาจารย์ใช้ Google Docs เขียนเอกสารร่วมกับนักศึกษา — **SaaS**
4. ใช้ Canva ออกแบบโปสเตอร์ — **SaaS**
5. Deploy แอป Python บน Google App Engine โดยไม่ต้องดูแล OS — **PaaS**

</details>
