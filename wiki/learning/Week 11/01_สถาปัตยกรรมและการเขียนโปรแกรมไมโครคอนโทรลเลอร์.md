# สถาปัตยกรรมและการเขียนโปรแกรมไมโครคอนโทรลเลอร์

ในฐานะวิศวกรคอมพิวเตอร์ การทำความเข้าใจ "ไมโครคอนโทรลเลอร์ (Microcontroller - MCU)" เปรียบเสมือนการทำความเข้าใจหัวใจหลักของระบบฝังตัว (Embedded Systems) ทั้งหมด ไมโครคอนโทรลเลอร์คือคอมพิวเตอร์ขนาดเล็กที่ถูกย่อส่วนให้อยู่ในไอซี (IC) เพียงตัวเดียว ประกอบด้วยหน่วยประมวลผลกลาง (CPU) หน่วยความจำ (RAM และ ROM/Flash) และพอร์ตอินพุต/เอาต์พุต (I/O Peripherals) ที่จำเป็นในการโต้ตอบกับโลกภายนอก

## สถาปัตยกรรมพื้นฐาน
การออกแบบสถาปัตยกรรมของ MCU มักแบ่งออกเป็นสองประเภทหลักตามการจัดระเบียบหน่วยความจำ:
1. **Von Neumann Architecture**: ใช้บัสข้อมูลและบัสที่อยู่ (Address Bus) ร่วมกันสำหรับทั้งคำสั่ง (Instructions) และข้อมูล (Data) ทำให้โครงสร้างเรียบง่ายแต่อาจเกิดคอขวด (Von Neumann Bottleneck) เมื่อต้องดึงข้อมูลและคำสั่งพร้อมกัน
2. **Harvard Architecture**: แยกหน่วยความจำและบัสสำหรับคำสั่งและข้อมูลออกจากกันอย่างชัดเจน ทำให้ CPU สามารถดึงคำสั่งและอ่านข้อมูลได้พร้อมกัน (Simultaneous access) สถาปัตยกรรมนี้เป็นที่นิยมอย่างมากในไมโครคอนโทรลเลอร์ยุคใหม่ เช่น ตระกูล AVR และ ARM Cortex-M

นอกจากนี้ ในเชิงชุดคำสั่งยังแบ่งเป็น **CISC** (Complex Instruction Set Computer) และ **RISC** (Reduced Instruction Set Computer) ไมโครคอนโทรลเลอร์ประสิทธิภาพสูงในปัจจุบัน (เช่น ARM) มักใช้สถาปัตยกรรมแบบ RISC เพื่อประหยัดพลังงาน ลดพื้นที่ซิลิกอน และสามารถประมวลผลคำสั่งส่วนใหญ่ได้ใน 1 รอบสัญญาณนาฬิกา

## การเขียนโปรแกรมไมโครคอนโทรลเลอร์
การพัฒนาซอฟต์แวร์สำหรับ MCU มีความท้าทายเฉพาะตัว เนื่องจากต้องจัดการกับข้อจำกัดด้านหน่วยความจำและพลังงาน ภาษาที่นิยมใช้ที่สุดในอุตสาหกรรมคือ **C และ C++** เนื่องจากมีความเร็วใกล้เคียงกับภาษา Assembly แต่ยังคงโครงสร้างระดับสูง ทำให้สามารถเข้าถึงและควบคุมฮาร์ดแวร์ได้โดยตรง

การเขียนโปรแกรมแบ่งออกเป็น 2 แนวทางหลัก:
- **Bare-metal Programming**: การเขียนโค้ดเพื่อควบคุมฮาร์ดแวร์โดยตรงผ่านการกำหนดค่าในรีจิสเตอร์ (Registers) โดยไม่มีระบบปฏิบัติการคั่นกลาง เหมาะสำหรับระบบที่ต้องการความแม่นยำของเวลาสูงสุด และซอฟต์แวร์มีขนาดเล็ก
- **RTOS (Real-Time Operating System)**: การนำระบบปฏิบัติการเวลาจริง เช่น FreeRTOS เข้ามาช่วยจัดการงานแบบมัลติทาสก์กิง (Multitasking) โดยรับประกันเวลาการตอบสนองสูงสุด (Deterministic Timing) ทำให้การจัดการโค้ดที่มีความซับซ้อนทำได้ง่ายขึ้น

### ตัวอย่าง: การเขียนโปรแกรมแบบ Bare-metal เบื้องต้น (ภาษา C)
```c
#include <stdint.h>

// สมมติที่อยู่ของรีจิสเตอร์สำหรับควบคุมพอร์ต GPIO
#define GPIO_DIR_REG  *((volatile uint32_t*)0x40020000)
#define GPIO_OUT_REG  *((volatile uint32_t*)0x40020004)

void delay(volatile uint32_t count) {
    while(count--) {} // หน่วงเวลาอย่างง่าย
}

int main(void) {
    // กำหนดให้พิน 5 เป็นโหมด Output
    GPIO_DIR_REG |= (1 << 5);

    while(1) {
        // เปิด LED (เซ็ตพิน 5 เป็นสถานะ High)
        GPIO_OUT_REG |= (1 << 5);
        delay(1000000);
        
        // ปิด LED (เซ็ตพิน 5 เป็นสถานะ Low)
        GPIO_OUT_REG &= ~(1 << 5);
        delay(1000000);
    }
    return 0;
}
```
*คำอธิบายทางวิศวกรรม:* โค้ดด้านบนแสดงการใช้คีย์เวิร์ด `volatile` เพื่อบอกคอมไพเลอร์ไม่ให้ทำการ Optimize โค้ดส่วนนี้ทิ้ง และใช้หลักการ Memory-mapped I/O โดยใช้พอยน์เตอร์ชี้ไปยังหน่วยความจำเชิงกายภาพของฮาร์ดแวร์รีจิสเตอร์โดยตรง ซึ่งเป็นหัวใจสำคัญในการเขียนโปรแกรมระดับต่ำ

การเข้าใจสถาปัตยกรรมฮาร์ดแวร์และการเขียนโปรแกรมระดับระบบเหล่านี้อย่างลึกซึ้ง จะเป็นฐานสำคัญที่ช่วยให้วิศวกรคอมพิวเตอร์สามารถออกแบบระบบฝังตัวที่มีประสิทธิภาพและเสถียรภาพสูงสุด

## ระบบฝังตัว (Embedded System) กับคอมพิวเตอร์อเนกประสงค์

ระบบฝังตัวคือระบบคอมพิวเตอร์ที่ออกแบบมาเพื่อทำ **หน้าที่เฉพาะ** และมักฝังอยู่ในอุปกรณ์ที่ใหญ่กว่า เช่น เครื่องซักผ้า รถยนต์ หรือเซนเซอร์ IoT ต่างจากคอมพิวเตอร์อเนกประสงค์ (General-purpose Computer) ที่ผู้ใช้ติดตั้งโปรแกรมได้หลากหลาย

| ประเด็น | ระบบฝังตัว (Embedded) | คอมพิวเตอร์อเนกประสงค์ (PC/Laptop/Server) |
|---|---|---|
| วัตถุประสงค์ | ทำงานเฉพาะอย่างซ้ำ ๆ (dedicated function) | ทำงานได้หลากหลาย ติดตั้งแอปเพิ่มได้ |
| ทรัพยากร | จำกัด: RAM ระดับ KB–MB, Flash ไม่กี่ MB | มาก: RAM ระดับ GB, SSD ระดับร้อย GB–TB |
| พลังงาน | ต่ำมาก (mW–W) บางตัวใช้แบตเตอรี่ได้เป็นปี | สูง (หลายสิบถึงหลายร้อย W) |
| ระบบปฏิบัติการ | ไม่มี (bare-metal) หรือ RTOS เช่น FreeRTOS | OS เต็มรูปแบบ เช่น Windows, Linux, macOS |
| เวลาจริง (real-time) | มักต้องตอบสนองภายในกำหนดเวลาแน่นอน | ไม่รับประกันเวลา (best-effort) |
| ต้นทุนต่อหน่วย | ต่ำ (หลักสิบถึงหลักร้อยบาท) ผลิตจำนวนมาก | สูง (หลักหมื่นบาทขึ้นไป) |
| ตัวอย่าง | ไมโครเวฟ, ระบบ ABS ในรถ, smart watch, เซนเซอร์ IoT, เครื่องวัดความดัน | คอมพิวเตอร์ตั้งโต๊ะ, โน้ตบุ๊ก, เซิร์ฟเวอร์ |

## ไมโครคอนโทรลเลอร์ (MCU) กับไมโครโปรเซสเซอร์ (MPU)

| ประเด็น | MCU (Microcontroller) | MPU (Microprocessor) |
|---|---|---|
| องค์ประกอบ | CPU + RAM + Flash + I/O (GPIO, ADC, UART ฯลฯ) **รวมอยู่ในชิปเดียว** | มีเฉพาะ CPU (และแคช) ต้องต่อ **RAM และหน่วยเก็บข้อมูลภายนอก** |
| ระบบปฏิบัติการ | bare-metal หรือ RTOS | รัน OS เต็มรูปแบบ เช่น Linux, Windows |
| ความเร็ว/หน่วยความจำ | สิบถึงหลายร้อย MHz, RAM ระดับ KB | ระดับ GHz, RAM ระดับ GB |
| พลังงานและการบูต | ใช้ไฟน้อย เริ่มทำงานแทบทันที | ใช้ไฟมากกว่า บูต OS หลายวินาที |
| ตัวอย่าง | ESP32, Arduino (ATmega328P), STM32 | CPU ใน Raspberry Pi (ARM Cortex-A), Intel Core / AMD Ryzen ใน PC |

> [!tip] จำง่าย
> MCU = "คอมพิวเตอร์ทั้งเครื่องในชิปเดียว" เหมาะกับงานควบคุม; MPU = "สมองอย่างเดียว" ต้องมีหน่วยความจำและอุปกรณ์รอบข้างบนบอร์ด เหมาะกับงานประมวลผลหนักที่ต้องใช้ OS

> [!info] ESP32 โดยสรุป (อ้างอิง Espressif datasheet และ ESP-IDF Chip Series Comparison)
> - **CPU:** ESP32 รุ่นดั้งเดิมใช้ Xtensa LX6 แบบ **dual-core 32-bit** ความถี่สูงสุด 240 MHz, SRAM 520 KB; รุ่นใหม่บางรุ่นใช้สถาปัตยกรรม [[RISC-V]] เช่น ESP32-C3 (single-core RISC-V 160 MHz) และ ESP32-C6
> - **การสื่อสารไร้สายในตัว:** Wi-Fi 2.4 GHz (802.11 b/g/n) และ Bluetooth (ESP32 ดั้งเดิม: Classic BR/EDR + BLE v4.2; ESP32-C3: Bluetooth 5 LE)
> - **พลังงานต่ำ:** มีโหมด Modem-sleep, Light-sleep และ **Deep-sleep** (กระแสระดับไมโครแอมป์) เหมาะกับอุปกรณ์ใช้แบตเตอรี่
> - **Peripherals:** GPIO, ADC, PWM, I2C, SPI, UART (บางรุ่นมี DAC และ touch sensor)
> - **การเขียนโปรแกรม:** ESP-IDF (C/C++), Arduino core (C++) และ MicroPython; ESP-IDF ใช้ FreeRTOS เป็นแกนหลัก
>
> สเปกต่างกันตามรุ่น ควรตรวจสอบ datasheet ของรุ่นที่ใช้จริงก่อนนำไปอ้างอิง

## ระบบเวลาจริง (Real-time System)

ระบบเวลาจริงไม่ได้แปลว่า "เร็ว" แต่แปลว่า **ต้องตอบสนองให้เสร็จภายในกำหนดเวลา (deadline)** ความถูกต้องของระบบขึ้นอยู่กับทั้งผลลัพธ์และ "เวลาที่ได้ผลลัพธ์"

| ประเภท | ถ้าพลาด deadline | ตัวอย่าง |
|---|---|---|
| **Hard real-time** | ถือว่าระบบล้มเหลว อาจเป็นอันตรายถึงชีวิต | ถุงลมนิรภัย (airbag) ต้องพองภายในเสี้ยววินาที, ระบบเบรก ABS, เครื่องกระตุ้นหัวใจ (pacemaker), ระบบควบคุมการบิน |
| **Soft real-time** | คุณภาพลดลง แต่ระบบยังใช้งานได้ | Video streaming (ภาพกระตุก), เกมออนไลน์ (lag), VoIP |

**RTOS (Real-Time Operating System)** คือ OS ที่ออกแบบให้การจัดลำดับงาน (scheduling) คาดเดาเวลาได้ (deterministic) เช่น ใช้ priority-based preemptive scheduling ให้งานสำคัญได้ CPU ทันที ตัวอย่างที่พบบ่อยคือ **FreeRTOS** ซึ่งเป็นแกนของ ESP-IDF บน ESP32

```c
// ตัวอย่าง: สร้าง 2 task บน ESP32 (ESP-IDF / FreeRTOS)
#include "freertos/FreeRTOS.h"
#include "freertos/task.h"

void sensorTask(void *pv) {
    while (1) {
        // อ่านเซนเซอร์ทุก 100 ms (งานสำคัญ priority สูง)
        vTaskDelay(pdMS_TO_TICKS(100));
    }
}

void wifiTask(void *pv) {
    while (1) {
        // ส่งข้อมูลขึ้น MQTT ทุก 5 วินาที (priority ต่ำกว่า)
        vTaskDelay(pdMS_TO_TICKS(5000));
    }
}

void app_main(void) {
    xTaskCreate(sensorTask, "sensor", 2048, NULL, 5, NULL);
    xTaskCreate(wifiTask,   "wifi",   4096, NULL, 3, NULL);
}
```

*คำอธิบาย:* `xTaskCreate` สร้างงานแยกกันพร้อมกำหนด stack size และ priority (5 สูงกว่า 3) scheduler ของ FreeRTOS จะให้ `sensorTask` ทำงานก่อนเสมอเมื่อถึงเวลา การอ่านเซนเซอร์จึงตรงเวลาแม้งานส่ง Wi-Fi จะใช้เวลานาน ส่วน `vTaskDelay` คืน CPU ให้งานอื่นระหว่างรอ แทนการวนลูปหน่วงเวลาแบบตัวอย่าง bare-metal ด้านบน

<details><summary>ดูเฉลย: ระบบนับก้าวใน smart watch เป็น hard หรือ soft real-time</summary>

เป็น **soft real-time** — ถ้าประมวลผลช้าไปบ้าง ค่าที่แสดงอาจหน่วงหรือคลาดเล็กน้อย แต่ไม่เกิดอันตราย ต่างจากการกระตุ้นจังหวะหัวใจใน pacemaker ซึ่งเป็น hard real-time
</details>
